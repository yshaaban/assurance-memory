# Fresh bounded agent study, 2026-09-08

All 16 submissions passed protected checks and independent blinded review of production mechanism and scope. **None of the eight B agents invoked the optional Assurance Memory CLI.** This study therefore demonstrates neither a retrieval benefit nor an efficiency benefit from the tool.

Three runs read installed generic workflow guidance outside their disposable project. Strict read-protocol eligibility is **13/16: A 7/8, B 6/8**. Mechanism acceptance, protocol eligibility and observed cost remain separate; all 16 assigned runs stay in the reported denominator.

## Design and protected evaluation

Four fresh symptom-only cards covered two controlled repairs, one bounded behavior-preserving simplification and one intentional no-change case. Each task ran twice under A (ordinary repository tools) and B (the same tools plus optional release 1.2 local CLI availability), producing 16 isolated runs across two private source snapshots. The tool was frozen at [release-1.2 commit c50f624](https://github.com/yshaaban/assurance-memory/commit/c50f624870c0e0ccaa595b9f5d57aaf4788cb734). Prompts named bounded subsystems without naming expected owner files. These tasks differed from the earlier calibration/development cases.

Task cards, source-owner labels with valid consumer alternatives, source inventories, evaluator checks, compiled tool inputs, model settings and schedule were frozen before launch. Seed 2026090813 randomized task/arm order within each repeat. Runs used Codex CLI 0.153.4, `gpt-6-astra`, medium reasoning, ephemeral JSON execution, ignored user configuration and a workspace-write sandbox. Both arms had the same 720-second wall ceiling; no token ceiling was enforced. At most two assigned runs overlapped.

Before launch, all four intact baselines passed their protected checks and all four controlled regressions failed them. After every agent exited, evaluation started from a trusted base and overlaid permitted production changes. Original tests/configuration remained evaluator-owned. Independent review required a correct mechanism and bounded scope; simplification also required one concrete future policy-edit owner, while no-change required a source-supported explanation. Candidate tests were supplemental. All four no-change runs left production unchanged; all four simplifications preserved protected behavior and centralized the named future policy change.

The primary acceptance reviewer was a separate senior-engineer AI agent. It received shuffled packets containing the task contract, source, production patch, submitted report and protected outcomes, with arm labels, obvious workspace paths and tool-specific prose removed. Final independent protocol audits were appended without rewriting those blinded mechanism judgments. This review is not independent human certification.

## Limitations and harness corrections

The four task-level mean B-minus-A provider-time differences were −28.438, +11.757, +36.041 and +19.148 seconds. Two repeats of each task are correlated, and the source snapshots are related development environments. No independent-run confidence interval, causal speed claim or broad product-value claim follows. The repair defects were controlled regressions in copies, not newly discovered defects in original repositories. The tasks exercised small policy owners inside larger components, not a release or browser-session validation.

The frozen runner sent provider final output to the same filename agents used for detailed authored reports. Final responses overwrote those reports. Detailed prose from the first two runs was lost; a subsequent evaluator-side read-only watcher preserved authored reports for the remaining 14. Prompts, provider invocation, source and oracles stayed frozen. One B aggregate formatting check also inspected an untouched tool reference file. These limitations remain attached to the original results.

After all 16 runs finished, the public harness was corrected to preserve authored reports and provider final responses separately, retain literal JSON arguments during placeholder expansion, kill remaining same-group descendants even after their leader exits, and charge/count integrity failures before provider launch. All 11 Python behavior tests and independent synthetic reproductions passed, including a fake-provider protected-overlay run. These checks made no additional model-provider requests. The exact executed harness was retained privately with its original frozen digest; the published harness contains those later corrections.

Separate workspaces, an environment allowlist, frozen hashes and trace review constrain this experiment, but they do not provide hermetic read containment. Candidate production code executes during protected tests. Repository-specific source, identifiers, owner labels, solutions and detailed artifacts remain private, so public readers cannot reproduce these particular task outcomes from this aggregate alone.

## Decision

The bounded mechanism and owner-navigation checks passed. The strict read protocol was not fully satisfied, and optional tool uptake was zero. There are no agent-issued search results from which to estimate ranking failures or retrieval effectiveness. Keep these results as a completed availability comparison; they do not justify a broader agent study or an assurance-value claim. Any later tuning informed by these tasks makes them development data and requires fresh evaluation cards.
